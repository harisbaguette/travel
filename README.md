# 🗺️ 여행 핀 지도

지도에 가고 싶은 곳을 콕콕 찍어 두고, 날짜별로 나눠 계획을 세우는 여행 앱.
로그인 없이 링크만 나눠 주면 친구와 같이 편집할 수 있다.

- 지도: 공식 구글 지도(Maps JavaScript API) — 열쇠가 있어야 뜬다. 지명·가게 종류가 한국어로 나온다
- 지도에서 누른 가게 정보: 구글 장소(Places)에 바로 물어본다 — 종류·영업시간·전화가 카드로 나온다
- 함께 편집: Neon (인터넷 Postgres) — 접속 주소가 없으면 자동으로 혼자 쓰기 모드

## 실행

```bash
npm install
npm run dev     # http://localhost:3000
```

## 기능

| 기능 | 설명 |
|------|------|
| 구글 지도 | 지명이 한국어로 나오고, 장소 검색도 구글맵과 같은 결과로 이동 |
| 핀 | 맛집🍜 관광지📸 카페☕ 숙소🛏 기타📍 — 추가·삭제·드래그·메모 |
| 비서 | 말로 부탁하면 네이버 블로그 후기를 찾아 핀 후보를 만들어 온다. 후보마다 출처 링크가 붙는다 |
| 여행 방 | 방마다 핀·일정 따로 저장. `?room=xxx` 링크로 참여, 방에 맞는 지도 위치로 이동 |
| 일정 타임라인 | Day 카드에 핀을 배정하고 방문 시각·순서 기록 |
| 여행 기록 | 비행(가는/오는 편)과 숙소(체크인/아웃) 기록 — 방 전체가 같이 본다 |
| 숙소 주소 | 구글 지도 공유 링크를 붙여넣으면 숙소 이름·지도 핀과 함께 **영문 주소**가 채워진다(입국·세관 서류의 체류지 칸에 쓰라고). 복사 단추로 바로 옮겨 담는다 |
| 모바일 | 하단 탭(지도/핀/일정/기록) + 내 위치 버튼 |
| 함께 편집 | 내 핀은 색 테두리, 친구 핀은 회색 점선 테두리 |

## 지도 켜기 (필수)

지도는 공식 구글 통로로만 뜬다. 열쇠가 없으면 지도 자리에
"지도를 불러오지 못했어요"만 나오고 핀·일정·기록 화면은 그대로 쓸 수 있다.

```bash
cp .env.example .env.local
# NEXT_PUBLIC_GOOGLE_MAPS_API_KEY=AIza...
```

만드는 순서: [console.cloud.google.com](https://console.cloud.google.com) → 프로젝트 생성 →
결제 카드 등록(무료 한도를 넘기 전에는 청구되지 않는다) → **Maps JavaScript API**와
**Places API (New)** 사용 설정 → 사용자 인증 정보에서 API 키 발급.

이 열쇠는 브라우저 화면에 그대로 드러나는 종류다(`NEXT_PUBLIC_`). 그래서 키 제한의
**HTTP 리퍼러**에 배포 주소와 `localhost`를 등록해 두어야 남이 갖다 쓰지 못한다.

장소 검색(검색창·비서의 좌표 찾기)은 열쇠가 없어도 열쇠 없는 구글 통로로 동작한다.
다만 그 통로는 구글이 공식으로 연 문이 아니라 형식이 바뀌면 조용히 빈 결과가 될 수 있다 —
열쇠를 넣으면 공식 장소 검색을 먼저 쓰고, 실패할 때만 예비 통로로 넘어간다.

## 함께 편집 켜기 (선택)

접속 주소가 없어도 앱은 그대로 동작한다 (내 브라우저에만 저장).
여러 사람이 같이 편집하려면 [Neon](https://neon.com)에서 무료 Postgres를 만들고
`.env.local`에 접속 주소를 넣는다:

```bash
cp .env.example .env.local
# DATABASE_URL=postgresql://...neon.tech/neondb?sslmode=require
```

테이블은 `src/lib/schema.sql` 한 파일에 다 들어 있다. Neon 콘솔의 SQL 편집기에
붙여넣거나 psql로 실행한다 (여러 번 실행해도 안전하다).

### 왜 폴링인가

Neon은 데이터베이스만 제공하고, Supabase처럼 "바뀌면 즉시 알려주는" 기능은 없다.
그래서 이 앱은 3초마다 "그 시각 이후 바뀐 것 있어?"라고 물어보는 방식으로 맞춘다.
바뀐 것만 골라 오므로 오가는 양이 적고, 다른 탭을 보고 있으면 아예 묻지 않는다.
두세 명이 여행 계획을 짜는 용도에는 이 정도로 충분하다.

## 비서 켜기 (선택)

비서(채팅으로 시키는 화면)는 AI 열쇠 하나만 있으면 움직인다. 없으면 비서 화면에만
안내가 뜨고 나머지 기능은 그대로 쓸 수 있다.

- **필수(둘 중 하나)** — `DEEPSEEK_API_KEY`
  ([platform.deepseek.com](https://platform.deepseek.com)) 또는 `OPENROUTER_API_KEY`
  ([openrouter.ai](https://openrouter.ai), `sk-or-`로 시작하면 자동으로 중개소 통로를 쓴다)
- **선택** — `NAVER_CLIENT_ID` / `NAVER_CLIENT_SECRET`
  ([developers.naver.com](https://developers.naver.com) → 애플리케이션 등록 →
  사용 API에 "검색" 선택). 없으면 블로그 홈의 공개 목록을 읽어 후기를 찾고,
  넣으면 공식 창구로 바뀌어 더 안정적이며 국내 가게 좌표도 정확해진다.

비서는 네이버 블로그 후기만 근거로 삼는다. 검색 결과에 없는 링크를 붙인 후보는
서버가 버리므로, 화면에 나오는 출처 링크는 실제로 열리는 글이다. 좌표는 AI가 부르는
값을 믿지 않고 서버가 이름·지역으로 직접 찾는다.

## 배포

Vercel에 그대로 올라간다. Vercel 프로젝트 환경 변수에 등록한다:

- `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` — 지도를 띄우려면 필수.
  키 제한의 리퍼러 목록에 배포 주소를 넣어 두어야 배포된 화면에서 지도가 뜬다
- `DATABASE_URL` — 함께 편집을 쓸 때
- `DEEPSEEK_API_KEY`(또는 `OPENROUTER_API_KEY`) — 비서를 쓸 때
- `NAVER_CLIENT_ID` / `NAVER_CLIENT_SECRET` — 비서의 후기 검색을 공식 창구로 바꿀 때(선택)
